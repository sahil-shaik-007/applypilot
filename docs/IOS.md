# ApplyPilot for iOS

The iOS app is the ApplyPilot PWA (`web/client`) wrapped by **Capacitor 8**. All screens and features live in the shared React code (see [MOBILE.md](MOBILE.md)). This document covers the native Xcode project, CI, signing, and App Store submission.

> **Before you submit to the App Store:** add **Sign in with Apple**. The app offers Google sign-in, and App Store Review Guideline **4.8 (Login Services)** requires an equivalent privacy-focused option, which in practice means Sign in with Apple. Without it the build will be rejected. See [Sign in with Apple](#sign-in-with-apple-required-by-guideline-48).

## Architecture

```
web/client/
├─ capacitor.config.json        appId com.applypilot.app, appName ApplyPilot, plugin config
├─ dist/                        built PWA (npm run build). Copied into the app by `npx cap sync ios`
└─ ios/
   ├─ App/
   │  ├─ App.xcodeproj          the Xcode project (one target: App)
   │  ├─ CapApp-SPM/            local Swift package that links Capacitor + every plugin (SPM)
   │  │  └─ Package.swift       GENERATED by `npx cap sync ios`. Never edit by hand
   │  └─ App/
   │     ├─ AppDelegate.swift   background runner, push, remote-notification wake-up
   │     ├─ SceneDelegate.swift window, dark background, deep links, Google redirect
   │     ├─ Info.plist          privacy strings, URL schemes, background modes, ATS
   │     ├─ App.entitlements    push, associated domains, Sign in with Apple
   │     ├─ Assets.xcassets     AppIcon (single 1024 px) + Splash (dark launch image)
   │     ├─ Base.lproj/LaunchScreen.storyboard   #0a0a0a launch screen
   │     └─ public/             web assets (generated, git-ignored)
   └─ scripts/icons.mjs         regenerates the icon + launch images (npm run icons:ios)
```

| Setting | Value |
|---|---|
| Dependency manager | **Swift Package Manager** (Capacitor 8 default; no CocoaPods, no `Podfile`) |
| Bundle ID | `com.applypilot.app` |
| Display name | ApplyPilot (`CFBundleDisplayName`). The Xcode target and product are named `App`, which is the Capacitor convention. Users never see it. |
| Deployment target | iOS **15.0**, the Capacitor 8 minimum |
| Devices | iPhone + iPad. iPhone is portrait-only. |
| Appearance | Forced dark (`UIUserInterfaceStyle = Dark`). The window and launch screen are `#0a0a0a`, so there's no white flash. |
| Version | `MARKETING_VERSION` 1.0.0. CI sets `CURRENT_PROJECT_VERSION` to the run number for every signed build. |
| Web content | Served from `capacitor://localhost`. `CapacitorHttp` sends `fetch` through native `URLSession`, so there's no CORS. |

### Plugins linked (via `CapApp-SPM`)

app, background-runner, browser, clipboard, device, filesystem, haptics, keyboard, local-notifications, network, preferences, push-notifications, share, splash-screen, status-bar, `@capgo/capacitor-native-biometric`, `@capgo/capacitor-social-login`, `@capgo/inappbrowser`.

After adding or removing a plugin in `package.json`, run `npx cap sync ios`. It rewrites `CapApp-SPM/Package.swift`. Commit that file.

### Native configuration and why

| Need | Where | Details |
|---|---|---|
| Biometric unlock (Face ID) | `Info.plist` `NSFaceIDUsageDescription` | Required by `@capgo/capacitor-native-biometric`. Without it the app crashes on Face ID devices. The DEK is stored only in the Keychain behind biometrics. This needs no extra entitlement. |
| Notifications | `UIBackgroundModes: remote-notification`, `aps-environment` entitlement, AppDelegate token forwarding | iOS has no custom text for the notification permission prompt. The UI explains the prompt before calling `requestPermission()`. |
| Background campaign checks | `UIBackgroundModes: fetch, processing`, `BGTaskSchedulerPermittedIdentifiers: com.applypilot.app.check`, `BackgroundRunnerPlugin.registerBackgroundTask()` in `didFinishLaunching` | The identifier must equal `plugins.BackgroundRunner.label` in `capacitor.config.json`. iOS decides when tasks actually run, roughly 30 s per run. **Background tasks never run in the Simulator.** To test on a device, pause in Xcode and run `e -l objc -- (void)[[BGTaskScheduler sharedScheduler] _simulateLaunchForTaskWithIdentifier:@"com.applypilot.app.check"]`. A silent push from ApplyPilot Cloud (`content-available: 1`) also wakes the runner (`remoteNotification` event). |
| Deep links | `CFBundleURLTypes`: `applypilot` | `applypilot://…` reaches JS as `App.addListener('appUrlOpen', …)` (forwarded by `SceneDelegateProxy`). |
| Universal links | `com.apple.developer.associated-domains`: `applinks:$(ASSOCIATED_DOMAIN)` | **Placeholder:** `ASSOCIATED_DOMAIN = app.applypilot.app` (build setting). Change it to the real `APP_ORIGIN` host. That host must serve `/.well-known/apple-app-site-association` with `{"applinks":{"details":[{"appIDs":["<TEAMID>.com.applypilot.app"],"components":[{"/":"/job/*"},{"/":"/share*"}]}]}}`. |
| Google Sign-In redirect | `CFBundleURLTypes`: `$(GOOGLE_IOS_REVERSED_CLIENT_ID)`, plus `GIDSignIn.handle(url)` in `SceneDelegate` | See [Google Sign-In](#google-sign-in-ios-client). |
| Files app | `UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace` | Exported resume PDFs appear under *On My iPhone › ApplyPilot*. |
| Camera / microphone / photo add | `NSCameraUsageDescription`, `NSMicrophoneUsageDescription`, `NSPhotoLibraryAddUsageDescription` | Some employer forms in the in-app browser have photo, video or voice inputs. Without these keys, WKWebView crashes the app when those inputs are tapped. |
| Export compliance | `ITSAppUsesNonExemptEncryption = NO` | The app uses only standard OS crypto (WebCrypto AES-GCM, PBKDF2, HTTPS), which is exempt. Confirm this when App Store Connect asks. |

### App Transport Security

HTTPS only: `NSAllowsArbitraryLoads = NO`. Debug builds also allow `http://localhost` and local-network addresses (`NSAllowsLocalNetworking`) for live reload against a dev server. The **"Strip debug ATS exceptions"** build phase deletes both exceptions from the processed `Info.plist` in **Release**, so App Store builds are strictly HTTPS. To check a release build: `plutil -p App.app/Info.plist | grep -A3 NSAppTransportSecurity`.

### "Share to ApplyPilot" from other apps

**Decision: no Share Extension target yet. The app uses the URL scheme and pasteboard fallback.**

A real Share Extension, which puts ApplyPilot in the share sheet of the LinkedIn, Naukri and Safari apps, needs:
- a second target, with its own bundle ID (`com.applypilot.app.share`) and provisioning profile
- an **App Group** (`group.com.applypilot.app`) on both App IDs, so the extension can hand the URL to the app, since extensions can't open their host app directly
- a small native plugin that reads the shared container on resume

The App Group and second profile can't be created or tested without the Apple Developer account. A hand-written second target also can't be verified on a real device from Windows. Adding it now would make CI's signed job fail until those exist.

What works today:
1. **URL scheme.** `applypilot://share?url=<encoded job URL>&text=<optional title>` opens the app. `share.onIncoming()` (mobile-native) parses this from `appUrlOpen`. Safari bookmarklets, Shortcuts (*Open URL*), and the desktop/web app can all hand jobs over this way.
2. **Pasteboard.** On resume, the app can offer "Use the job link you copied?" via `@capacitor/clipboard`. iOS shows its paste-permission banner, so the app should only read the clipboard after a user tap.
3. **Shortcuts.** A one-step Shortcut ("Share to ApplyPilot": *Receive URLs from Share Sheet → Open `applypilot://share?url=[Shortcut Input]`*) puts ApplyPilot in every share sheet with no extension. Document it in the in-app help.

When the Apple account exists, add the extension in Xcode (*File › New › Target › Share Extension*). Enable the App Group on both targets, write the shared URL to `UserDefaults(suiteName:)`, and add the App Group, extension bundle ID and second profile to the signing secrets. The CI `testflight` job then needs a second `provisioningProfiles` entry.

## Building on a Mac

Requirements:
- macOS with **Xcode 26** or newer (Capacitor 8's floor; use the Xcode on the CI image)
- Node 24
- an Apple ID, for running on your own device

```bash
cd web/client
npm ci
npm run build            # builds dist/
npx cap sync ios         # copies dist/ into the app, regenerates CapApp-SPM/Package.swift
npx cap open ios         # opens App.xcodeproj; Xcode resolves Swift packages on first open
```

In Xcode:
1. Select the **App** target, then *Signing & Capabilities*, and pick your Team.
2. Choose a simulator or device and press **Run**.

Command-line simulator build (exactly what CI does):

```bash
cd web/client/ios/App
xcodebuild build -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath build/DerivedData -clonedSourcePackagesDirPath SourcePackages \
  CODE_SIGNING_ALLOWED=NO
xcrun simctl install booted build/DerivedData/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch booted com.applypilot.app
```

Live reload: `npx cap run ios --live-reload --host <your LAN IP>`. The Debug ATS exception allows the http dev server.

On Windows you can edit everything except Xcode-managed UI files. `npx cap add/sync ios` works on Windows. Swift package resolution and compilation happen in CI.

### Icons and launch screen

```bash
cd web/client
npm run icons:ios        # = node ios/scripts/icons.mjs
```

- **Icon source:** `assets/brand/png/background-1024.png` with `foreground-1024.png` (the mark enlarged for iOS). If those are missing, it falls back to `assets/brand/png/icon-1024.png`, then `build/icon.png`. The result is flattened to an **opaque, square, un-rounded** 1024 px PNG, as Apple requires.
- **Launch image:** `assets/brand/png/mark-512.png` centred on `#0a0a0a`, in light and dark variants.
- The script runs `@capacitor/assets` (`capacitor-assets generate --ios`) and deletes stale images. Re-run it after any logo change and commit `ios/App/App/Assets.xcassets`.

## CI: `.github/workflows/ios.yml`

**Triggers:**
- pushes to `main`, `ci/ios-*` and `v*` tags that touch `web/client/**`, `web/shared/**` or the workflow
- pull requests
- manual runs (`workflow_dispatch`)

| Job | Runner | What it does |
|---|---|---|
| `simulator` | `macos-latest` | 1. Node 24 → `npm ci` → `npm run build` → `npx cap sync ios`. 2. Boots the newest iPhone simulator. 3. `xcodebuild build` for that simulator (no signing). 4. Zips `App.app` into the **`ApplyPilot-simulator-app`** artifact. 5. Installs and launches the app, checks it's still running after 25 s, and saves `xcrun simctl io booted screenshot` images plus the app log to the **`ios-screenshots`** artifact. |
| `signing-check` | `ubuntu-latest` | Outputs whether the signing secrets exist. |
| `testflight` | `macos-latest` | Runs only when the secrets exist, and never on PRs. 1. Imports the certificate into a temporary keychain and installs the profile. 2. Switches the App target to manual "Apple Distribution" signing. 3. `xcodebuild archive`, then `-exportArchive` (app-store-connect) into the **`ApplyPilot-ipa`** artifact. 4. Uploads to **TestFlight** with `xcrun altool` on `v*` tags, or on a manual run with `testflight: true`. |

**Caching:**
- npm (`setup-node`)
- Swift package checkouts (`ios/App/SourcePackages`), keyed on `CapApp-SPM/Package.swift` and `package-lock.json`

macOS minutes on private repos are billed at 10×. The simulator job takes about 10–15 minutes warm.

### Signing secrets (repository → Settings → Secrets and variables → Actions)

| Secret | How to get it |
|---|---|
| `APPLE_TEAM_ID` | developer.apple.com → Membership → Team ID (10 characters) |
| `BUILD_CERTIFICATE_BASE64` | Create an **Apple Distribution** certificate (Certificates → +), install it, export it from Keychain Access as `.p12`, then `base64 -i dist.p12 \| pbcopy` |
| `P12_PASSWORD` | The password you set on that `.p12` export |
| `BUILD_PROVISION_PROFILE_BASE64` | Profiles → + → **App Store Connect** distribution profile for App ID `com.applypilot.app`, then `base64 -i ApplyPilot_AppStore.mobileprovision \| pbcopy`. Regenerate it whenever you change capabilities. |
| `APP_STORE_CONNECT_API_KEY_ID` | App Store Connect → Users and Access → Integrations → **App Store Connect API** → generate a key (role *App Manager*). Its Key ID. |
| `APP_STORE_CONNECT_ISSUER_ID` | The Issuer ID shown on the same page |
| `APP_STORE_CONNECT_API_KEY_P8_BASE64` | `base64 -i AuthKey_XXXXXXXXXX.p8 \| pbcopy`. The `.p8` can only be downloaded once. |

The App ID `com.applypilot.app` must have these capabilities enabled **before** you create the profile, or signing fails with an entitlements mismatch:
- **Push Notifications**
- **Associated Domains**
- **Sign in with Apple**

Also create an APNs key (Keys → + → APNs) for ApplyPilot Cloud to send pushes.

## Google Sign-In (iOS client)

1. Google Cloud Console → APIs & Services → Credentials → *Create OAuth client ID* → **iOS**. Use bundle ID `com.applypilot.app` and add your Team ID.
2. Copy:
   - the **iOS client ID** (`1234-abc.apps.googleusercontent.com`)
   - its **reversed client ID** (`com.googleusercontent.apps.1234-abc`)
3. In Xcode (or `project.pbxproj`), set the build setting `GOOGLE_IOS_REVERSED_CLIENT_ID` to the reversed ID. It feeds the second `CFBundleURLTypes` entry. It's currently a placeholder (`com.googleusercontent.apps.REPLACE-WITH-IOS-CLIENT-ID`).
4. In JS (mobile-native), call `SocialLogin.initialize({ google: { iOSClientId: '<iOS client ID>', iOSServerClientId: '<web client ID>' } })`.
5. **Server (cloud):** the ID token minted for the iOS client may carry the **iOS client ID** as `aud`. `web/server` must accept a list of audiences (web, iOS and Android client IDs), not only `GOOGLE_CLIENT_ID`.
6. The Google OAuth consent screen must be **published**, not in "Testing", before App Review. Otherwise reviewers can't sign in.

## Sign in with Apple (required by guideline 4.8)

**Status: entitlement added, UI not implemented. Recommended before the first App Store submission.**

- Guideline 4.8 says apps that use a third-party login service (Google) must also offer an equivalent option that:
  - limits data to name and email
  - lets users keep their email private
  - doesn't track them

  Sign in with Apple meets all three. Apps that use Google only will be rejected.
- `@capgo/capacitor-social-login`, already installed, ships an **`apple`** provider: `SocialLogin.initialize({ apple: {} })` and `SocialLogin.login({ provider: 'apple', options: { scopes: ['email', 'name'] } })`. The `com.apple.developer.applesignin` entitlement is already in `App.entitlements`.
- Work still needed:
  - **UI (mobile-features):** an Apple button with the same prominence as Google, following Apple's button guidelines.
  - **Server (cloud):** `POST /api/auth/apple`, which verifies the Apple identity token (JWKS at `https://appleid.apple.com/auth/keys`, `aud = com.applypilot.app`, `iss = https://appleid.apple.com`). It must handle relay emails (`@privaterelay.appleid.com`) and the name arriving only on first sign-in.
  - **Account deletion:** already offered (`DELETE /api/account`). Guideline 5.1.1(v) also requires revoking the Apple token on delete (`https://appleid.apple.com/auth/revoke`).

## App Store / TestFlight checklist

**Account and setup (user)**
- [ ] Apple Developer Program membership ($99/yr) in the publisher's legal name (or an organization with a D-U-N-S number)
- [ ] App ID `com.applypilot.app` with Push Notifications, Associated Domains and Sign in with Apple enabled
- [ ] Distribution certificate, App Store provisioning profile, and App Store Connect API key, all added as CI secrets (above)
- [ ] App Store Connect → *My Apps* → **+** → New App (iOS, bundle `com.applypilot.app`, SKU `applypilot-ios`)
- [ ] APNs key uploaded to the server config, if push is used

**Build**
- [ ] Real `ASSOCIATED_DOMAIN`, `apple-app-site-association` served, `GOOGLE_IOS_REVERSED_CLIENT_ID` set
- [ ] Sign in with Apple implemented (guideline 4.8)
- [ ] `npm run icons:ios` with the final logo
- [ ] Tag `vX.Y.Z` (or run the workflow manually with `testflight: true`), wait for processing, then add internal testers in TestFlight
- [ ] External TestFlight testing needs a Beta App Review: test notes and a demo account

**App Review notes.** Give reviewers:
- a **demo account**: a Google or Apple test login plus a vault passphrase
- a clear explanation that auto-fill **only fills** forms on employer sites the user opens. It never submits on LinkedIn, Indeed, Naukri, Glassdoor, Workday or unknown sites, and auto-submit on allow-listed ATSs happens only after a visible cancel window. This addresses guideline 2.5.6 and the reviewer's "automation" questions.
- the statement that AI features use the user's own Anthropic API key (guideline 3.1.1: not a purchase)

**Payments.** Desktop licenses are sold through Dodo Payments. Inside the iOS app, **don't** link to or mention external purchase of digital features unless you use Apple's External Purchase Link entitlement where allowed, or IAP. The safest v1 is a free iOS app with no purchase UI.

**Privacy policy URL.** Required. `docs/PRIVACY.md` covers only the desktop app ("we collect nothing"). Publish an updated policy that covers ApplyPilot Cloud and the mobile apps before you submit.

**App Privacy ("nutrition label").** Derived from [PRIVACY.md](PRIVACY.md) and [CLOUD.md](CLOUD.md). Have the server owner confirm it before you submit.

| Data type (Apple category) | Collected? | Linked to user | Tracking | Purpose | Source |
|---|---|---|---|---|---|
| Contact Info → **Email address** | Yes | Yes | No | App functionality (account) | Google/Apple sign-in. The server stores the email. |
| Contact Info → **Name** | Yes | Yes | No | App functionality | Google profile name |
| Identifiers → **User ID** | Yes | Yes | No | App functionality | Server account ID, session and device tokens |
| Search History → **Search history** | Yes | Yes | No | App functionality | Job search queries run on the server (15-min cache, not logged per CLOUD.md) |
| User Content → **Other user content** (profile, resumes, applications, answers) | **Not "collected"**: end-to-end encrypted, and the server holds only ciphertext it can't read | n/a | No | n/a | Apple treats data the developer can't access as not collected. State this in the privacy policy. |
| Photos (Google avatar URL) | Optional: declare under Contact Info → Other if the avatar is stored | Yes | No | App functionality | Google profile picture URL |
| Diagnostics / Usage / Location / Financial / Health / Contacts | **No** | | | | No analytics, crash SDK, location or payments in the app |

The AI calls go straight from the device to Anthropic with the **user's own** key, and the developer never receives them. Mention this in the privacy policy as a user-directed third-party service.

**Third-party SDK check.** `@capgo/capacitor-social-login` links the **Facebook SDK** (and GoogleSignIn) even though ApplyPilot doesn't use Facebook login. Before submitting:
1. In Xcode Organizer, run *Product › Archive › Generate Privacy Report*.
2. Confirm that no SDK declares `NSPrivacyTracking = true` or collected data you haven't disclosed.
3. If the Facebook SDK's manifest declares tracking, either declare it or (better) switch to a Google/Apple-only login plugin so the Facebook SDK isn't linked.

**Other metadata:**
- Age rating questionnaire (expect 4+)
- Category: Business or Productivity
- Screenshots for 6.9″ and 6.5″ iPhone, plus 13″ iPad because the app supports iPad (or remove iPad support with `TARGETED_DEVICE_FAMILY = 1`)
- Support URL and marketing URL

## Known limitations

- Background tasks don't run in the Simulator, and iOS schedules them opportunistically. Don't promise exact check intervals.
- The CI screenshot shows the app's first screen (sign-in / landing). It proves the native shell, plugins and web bundle load. It doesn't exercise signed-in flows.
- The service worker isn't used inside the app: WKWebView doesn't run service workers on the `capacitor://` scheme. Assets are bundled, so offline still works.
